# 2026.272.1009 — feat(skills): author the owning transcode skill entity (#291)

## Summary

The `plugin-media` candy repo declared **no `skill:` entity**, so no owning
`/charly-check:transcode` skill was projected into the marketplace corpus and the
repo's `AGENTS.md` R0 list had no owning skill to name (#291, batch C).

This plugin has a **distinct user-facing procedure with no existing corpus page**:
a sweep of `origin/main` over `*skills/*/SKILL.md` for `transcode`, `verb:transcode`,
and `transcode:` returns **zero pages** (the only `mjpeg`/`libx264` hits are the
unrelated `/charly-check:spice` and `/charly-selkies:*` pages). So this is an
**author**, not a record.

The org convention is a **sibling top-level entity** named `<candy>-skill:` (NOT a
nested block inside the candy node), proven across the corpus (`ripgrep-skill:`,
`nvidia-skill:`, `supervisord-skill:`, `yay-skill:`, `kind-skill:`, `wl-skill:`,
`punktfunk-skill:`) and by the merged #291 siblings (`android-sdk-skill:`,
`cachyos-extras-skill:`, `android-test-apps-skill:`) and the open batch-D sibling
(`desktop-media-skill:`). This adds `transcode-skill:` as a new top-level node,
corrects the README owning-skill line, and updates the `AGENTS.md` R0 list to name
`/charly-check:transcode`.

The entity is authored from the real manifest + Go source: `verb:transcode` with
primary field `to`; the input contract from `schema/transcode.cue`
(`source_artifact`/`to`/`artifact`/`artifact_min_bytes`/`artifact_not_uniform`);
the canonical ffmpeg invocation + the RDD-3 `artifact_not_uniform`-on-SOURCE rule
from `transcode.go`.

import yaml
sk = yaml.safe_load(open('candy/plugin-media/charly.yml'))['transcode-skill']['skill']

for k in ('name','family','owner','description','content'):
