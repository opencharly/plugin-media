# 2026.254.0445 — refactor(media): land post-transcode validation via sdk.LandArtifact (G-8/G-9)

## Summary

Migrate plugin-media's artifact handling to the shared `sdk.LandArtifact` write-then-validate tail (approved plan G-8/G-9).

- Bump `github.com/opencharly/sdk` to **v0.2026254.439** (the tag of sdk#249, which landed the `LandArtifact` host leg). `go mod tidy` also resolves spec to v0.2026250.2036 (MVS requirement of the new sdk — same PR, build-consistent).
- `sdk.VerbVerdict` now runs the shared exit/stdout/stderr matchers **only** (`artifact=false`); the artifact validators no longer run inside the verdict pipeline.
- The post-transcode write-then-validate tail is now the **SAME `sdk.LandArtifact(ctx, nil, "", out, &val)` call every artifact-producing plugin uses** — host leg (nil executor + blank venue path): nothing is pulled or written, `sdk.RunArtifactValidators` ALWAYS runs on the existing host path (artifact_min_bytes / min_dimensions / min_cast_events / contains_text). Validator failure returns the same `transcode: transcode: <err>` wire shape as before.
- The plugin's own ffmpeg pipeline (`runTranscode`) is unchanged; the source-frame `artifact_not_uniform` check (RDD-3, pre-encode on the MJPEG) keeps its plugin-local binding and stays stripped from the copy handed to the shared validators.
- No direct `RunArtifactValidators` call existed in the plugin (validation rode inside `VerbVerdict`'s `artifact=true` leg); that leg is what this removes.
